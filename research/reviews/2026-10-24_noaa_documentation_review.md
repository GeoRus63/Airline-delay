# NOAA GHCNh schema and fill-map review — 2026-10-24

Read-only evidence review of `references/noaa_ghcnh_documentation.pdf` (18 pages), the NOAA preparation/fill code, and 500-row samples from each of the 25 compressed station files (12,500 rows total). No full raw file scan or flight labels were used. The PDF is the local official GHCNh document; its page references below are printed PDF page numbers.

## Findings

| Contract | Official documentation | Current implementation / result |
|---|---|---|
| Metadata grain and field names | p.6 documents each element followed by measurement, quality, report-type, source, and source-station metadata. p.18 points to a separate columns document. | `prepare_weather.py:45-59` selects each element and its metadata; `:542-547` reads metadata as strings, avoiding numeric source-code coercion such as `313` to `313.0`. The official [GHCNh columns reference](https://www.ncei.noaa.gov/oa/global-historical-climatology-network/hourly/doc/ghcnh-columns.pdf), pp.1-10, defines one `*_Quality_Code` string and one `*_Source_Code` string per element. It lists no independent post-integration QC column. Samples from all 25 local raw station files confirmed these headers; source `223`/QC `1` was common and source `413`/blank QC was present. This does not establish every QC serialization combination.
| Temperature / dew point | p.7: degrees Celsius, tenths. | `weather_features.py:48-49` Celsius-to-Fahrenheit mapping is dimensionally valid. These fields are now overlap/audit-only under the fixed G4a fill policy (`:63-68`).
| Wind direction / speed / gust | p.7: true-north degrees (360 north; 000 for calm), m/s; gust is a short-duration peak exceeding average wind speed. | `weather_features.py:50,52-53` identity degrees and m/s-to-knots are dimensionally valid. Direction semantics at calm/zero need care; NOAA direction is not filled into G4a. Wind and gust unit conversions are supported.
| Visibility / ceiling | p.7: visibility is km; p.8: ceiling is AGL meters, lowest cloud/obscuration with at least 5/8 summed sky cover or vertical visibility, with method/CAVOK details. | `weather_features.py:54-55` km-to-mile and m-to-feet are dimensionally valid. NOAA ceiling's source definition is not necessarily identical to METAR's cloud-group construction; current fill is restricted to cases where the METAR report is wholly missing or sky is explicitly unreported (`:63-68`, `:265-271`).
| Relative humidity | p.7: whole percent, measured directly or calculated from temperature/dew point depending on source. | `weather_features.py:51` identity % is valid as a unit conversion, but the documented source-dependent derivation means its measurement basis varies. It is excluded from G4a NOAA filling.
| Precipitation and weather codes | p.7: precipitation is liquid equivalent rain/melted-snow total, nominally hourly and can include intermediate reports. p.9-11 list multi-hour/5/15-minute elements and source-specific measurement flags. p.17 says METAR/SPECI precipitation can be a running accumulation through the hour; use the final report for the hourly total. p.7 says present-weather code definitions live in a separate PDF not present here. | Precipitation is not mapped to METAR `p01i`; precipitation periods and reporting cadence cannot be proven equivalent (`weather_features.py:70-74`). NOAA present weather is not mapped to METAR rain/snow/thunder flags. Snow depth is ground snowpack (p.7), not precipitation.

That is proven for precipitation, but the reviewed PDF does not establish the same sentinel for every other element; confirm with the separate columns/sentinel documentation before treating this broader mask as source-verified.

## Quality and measurement code checks

- `prepare_weather.py:39-43,457-476` implements these strict legacy QC choices. The source-specific code semantics match p.13: sources 313/314/315/322/335/343/344/346 accept only `1` (passed all QC) or `5` (passed all QC, NCEI-origin); sources 220/221/222/223/347/348 accept only `1` (Good). Code `0` for the first family is only gross-limits pass, and `0` for the second family is not checked; neither is accepted. Suspect, erroneous, removed, or unrecognized values are rejected.
- Source 345 is only documented on p.15 for relative humidity and wind speed: `0=Good`, `1=Issue`, `3=Error`. `prepare_weather.py:471-472` accepts only QC `0` on those two elements. It rejects source-345 blank QC and all other source-345 elements.
- Source 382 is specifically the C-HPD precipitation source. p.14 defines blank QC as not failing QA checks and lists nonblank flags including failed checks; `A` explicitly means the total is for an accumulation longer than an hour. `prepare_weather.py:463-474` accepts blank QC only for precipitation and rejects every nonblank QC value. This is a QA eligibility decision, not proof the accumulation window matches a METAR hour; no NOAA precipitation fill is enabled.
- p.13 also lists post-integration general QC checks for temperature, dew point, station/sea-level pressure, wind direction, and wind speed, with code descriptions, while stating other elements retain component-source QC. The official [GHCNh product page](https://www.ncei.noaa.gov/products/global-historical-climatology-network-hourly) likewise states that general QC runs after source integration and that component-source QC is preserved. The official columns document shows only one `*_Quality_Code` string per element and no separate integration-QC column. However, neither official reference specifies the encoding precedence or whether multiple relevant flags are concatenated in that field. Therefore the field is the only serialized per-element QC field, but it cannot be certified from the available documentation as a combined final pass/fail verdict. The current exact-string whitelist (`qc in {"1","5"}` or `{ "1" }`) rejects appended/alternate flags; it accepts only documented source/code pairs and remains a sensitivity eligibility screen, not full post-integration-QC certification.
- The official [GHCNh source list](https://www.ncei.noaa.gov/oa/global-historical-climatology-network/hourly/doc/ghcnh-source-list.pdf) identifies source 223 on p.2, 313 on p.12, 343 on p.14, and sources 345/382/412/413 on p.15. In particular, source 413 is NOAA-decoded METAR/FM15/FM16; 413 is not in the documented whitelist, and blank QC is excluded by `prepare_weather.py:457-476`. In the limited 12,500-row raw sample, source 413 appeared with blank quality codes for several elements, while a source-223 temperature row with QC `2` appeared and is rejected by the exact whitelist. This supports conservative exclusion of unrecognized blank flags; it does not prove all currently eligible observations pass every generalized check.
- Measurement codes on p.10: `2=Trace` is documented for the enumerated legacy source families; `1=measurement impossible/inaccurate`. Source 343's `precipitation_5_minute` specifically uses `T` for trace. p.11 defines source-382 `T=trace`, `XX` as accumulation hours, and additional carryover measurement flags. `prepare_weather.py:479-496` now scopes code `2` to documented source families and `T` to source 382 for the generic precipitation element; code `1` is marked invalid, and other nonblank codes are labeled source-specific rather than ordinary measured. Raw codes remain available. This avoids interpreting source-382 `2` or an unknown source's `2` as a documented trace.

The precipitation trace status does not by itself imply the value is suitable as an hourly numeric amount. In particular, source-382 `A` is rejected by QC and signifies a greater-than-one-hour accumulation. The project should continue to preserve per-element source, report type, measurement code, and QC with any NOAA precipitation product.

## NOAA-to-METAR fill decision

The project plan's G4a set is wind speed, gust, visibility, ceiling, ended-observation precipitation, and weather occurrence flags (`docs/完整项目计划.md:60-63`). The documented NOAA precipitation period and weather-code limitations leave only wind speed, gust, visibility, and ceiling candidates. `NOAA_METAR_FILL_MAP` retains other dimensionally valid fields for overlap diagnostics (`weather_features.py:47-55`), while `NOAA_METAR_FILL_POLICY` now limits fills to the four G4a fields (`:63-68`): wind/visibility can fill their missing value; gust can fill only when the whole METAR is unavailable; ceiling can fill only when the whole METAR is unavailable or sky is unreported. Thus a valid METAR sky report with no ceiling (e.g. clear/FEW/SCT) and a valid report with no gust are preserved as structural missingness. `augment_noaa` retains per-field source, QC, station, file, observation-time, age, and fill counts (`:236-290`).

The GHCNh observation-time plus five-minute availability and 120-minute age limit remain retrospective sensitivity assumptions. The official schema contains observation time but no verified historical dissemination/receipt timestamp; this data cannot prove that NOAA values were received by the modeled prediction time. The code and preparation summary correctly mark this limitation rather than claiming historical live availability.

## Remaining evidence gaps

1. The official source-list and columns documents were checked online, but they are not local project references. `ghcnh-present-weather-elements.pdf` and the cited Copernicus land-data user guide are still absent. Generalized-QC precedence/serialization remains unspecified in the official documents inspected.
2. The 500-row-per-file sample confirms schema plus limited observed source/QC formats only. It cannot prove all source frequencies, all sentinel conventions, or historical publication time.
3. Source-382 blank QC means “did not fail a QA check,” not “hourly and suitable for any feature.” `A` periods and report/measurement metadata must remain available if precipitation is ever evaluated separately.

## Follow-up implementation note

Because the official serialization remains unspecified, the NOAA branch now records `noaa_postintegration_qc_serialization_verified=false` and a limitation statement in the preparation summary and augmented-frame audit attributes. It accepts only the exact documented source/QC pairs; unknown or blank QC such as source 413 remains ineligible. Treat the NOAA branch as a retrospective sensitivity analysis, not a fully certified post-integration-QC subset.

METAR missingness now retains `metar_missing_reason` with `no_observation`, `stale_observation`, `conflicting_reports`, or `available`. NOAA backfill checks the ambiguity field emitted by `augment_metar` (`metar_metar_ambiguous` under its current feature prefixing) and never fills a conflicting duplicate group. The sensitivity fill still cannot establish historical receipt availability.
