## 1. 环境与文件迁移

本次研究环境是项目内 `.venv`，实际 Python **3.13.15**，`include-system-site-packages=false`，由 `E:\PythonEnvs\general\python.exe` 创建。旧版《迁移与运行》中的 Python 3.12 是早期建议，不是本次模型运行的实际解释器。

- `requirements.txt` 固定 11 项直接依赖；`requirements.lock.txt` 是本次完整依赖锁定清单，包含 scipy、joblib、psutil 等传递或执行依赖。实际文件名包含 `.lock.txt`。
- 模型、数据处理、Notebook 和指标使用 `.venv`。每轮 `manifest.json` 另外记录实际 Python、全部已安装包、Git 提交和命令，环境清单不能只看直接依赖。
- PDF 与 PPTX 使用独立 Codex artifact runtime。本机其 Python 为 **3.12.14**，带 `reportlab 4.4.9`、`pypdf 6.10.0`；项目 `.venv` 未安装这两包。公式图片由项目 `.venv` 的 matplotlib 子进程生成。不要为了渲染报告改写已验证的模型环境。
- 本次 lock 包含 Windows 组件；同平台同 Python 版本复建优先使用该 lock。更换平台或依赖版本后，应记录新环境并实际核对数值，不能预先宣称完全等价。

已有 `.venv` 时只检查；新机器或独立副本尚无环境时才创建：

```powershell

& 'E:\PythonEnvs\general\python.exe' -m venv .venv
$Py = Join-Path (Get-Location) '.venv/Scripts/python.exe'
& $Py -m pip install -r requirements.lock.txt
& $Py --version
& $Py -m pip check
```

保留完整 Git 历史。`select_models.py` 会读取登记提交 `6357cd4d11882d01a70b64200356b9626004103d` 的协议，归档审计也会读取各轮历史源码 blob；浅克隆不足时先补齐历史。不要复制旧 `.venv` 到另一台机器，重新创建环境。

**Git 克隆不是完整研究备份。** `raw/` 的完整字节、`processed/`、所有 run 的 `data/`、`predictions/`、`models/`、冻结文件和正式 ledger 都应同步并按收据核对。`.gitignore` 明确忽略 `processed/*` 和 run 内三类大文件；原始输入虽已纳入交付清单，迁移后仍须核对是否全部在本地。仅有轻量配置、指标或 Notebook，不能证明模型或全流程可复现。还应保留 `references/taf_validity.csv` 等未跟踪的生成文件。不要删除或重写已完成 run。

正式 run 及其流水线 manifest 都完成后，复制正式配置为新的复现配置，仅把 mode 改成 `reproduce_final`，stage 改为 P7，更新 change/parent；**保留原 freeze 路径和原 SHA**，不加入开发 `feature_archive_path`。提交该配置并用新编号运行：


该模式自动定位唯一 completed 正式 ledger，核对相同冻结/源码/输入，然后实际重建全特征、使用同一成熟训练/测试划分、重新拟合相同学习模型与三个基线并重新预测。核对训练/测试 IDs、targets、完整实际特征类型和值指纹；逐行比较 raw/clip 预测以及指标，当前固定绝对容差 `1e-10`、相对容差 0，配置不能放宽。保存 `reproduction_reference.json`、`reproduction_prediction_differences.csv`、`reproduction_verification.json` 和明确标注“完整复现”的 07；只写新 run，不改正式 ledger 或主 07。失败也保留，不能冒充新独立测试。

只读复现核对与完整复现的区别：前者检查已保存计算证据；后者重新构建、重拟合、预测。前者报告 `refitted=false/raw_test_data_read=false`，完整复现的执行来源收据记录实际 refit/raw read。两者不能互相替代。
