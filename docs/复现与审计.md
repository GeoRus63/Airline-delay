# 复现与归档审计

本说明对应当前 `codex/apr-aug-research` 分支的实际脚本。研究规则见[完整项目计划](完整项目计划.md)，实验过程见[研究记录](../research/研究记录.md)及[实验索引](../experiments/index.csv)。现有 `scripts/run_pipeline.py` 每次执行一个 JSON 配置；没有从下载到报告的一键总入口。

## 1. 核验与复现范围

**复核现有结果**：核对索引、收据、历史源码、环境；最终模型使用已保存预测重新计算指标。这不训练模型，也不重新打开原始 8 月目标。

**重新计算开发实验**：在独立工作副本和新 `run_id` 中，按 P0→P5 顺序重建派生数据、拟合开发模型并重新分析。此过程会读取开发期数据、占用较多 CPU/内存/磁盘。不能覆盖原运行，也不能把失败或失效运行改成成功。

**完整复现冻结最终实验**：正式评估完成后，`mode="reproduce_final"` 在新 `run_id` 中验证原冻结、源码和输入，重新构建特征、拟合原学习模型与三个基线，并比较完整训练/测试特征、IDs、标签、逐行预测和指标。原正式访问账本只读；这是已见测试结果的机械复现，不是第二次独立验证。

8 月预测窗为 `[2026-08-01 00:00 UTC, 2026-09-01 00:00 UTC)`。正式评估由冻结文件与 `experiments/final_access/2026-08.json` 单次门禁控制。已完成后的例行复核使用保存预测，不能再调参或重新选择模型。

## 2. 获取当前分支与创建环境

原始航班、天气档案和参考资料已随仓库保存；正常搬迁无需重新下载。保持相对目录结构及 `.gitattributes` 的字节保留规则。完整历史用于按每轮 `git_commit` 读取历史源码，审计副本不要采用 shallow clone。

从当前本机分支复制到一个尚不存在的新目录，例如 PowerShell 7：

```powershell
git clone --branch codex/apr-aug-research D:\Airline-delay D:\Airline-delay-replay
Set-Location D:\Airline-delay-replay
git branch --show-current
git rev-parse HEAD
```

该命令使用已提交内容；未提交文件和被忽略文件不会自动复制。若该分支已推送到远端，也可将源路径替换为 `https://github.com/GeoRus63/Airline-delay.git`，仍显式指定分支。不要假定远端已经包含本机尚未提交或推送的工作。

本轮实际环境使用 Python **3.13.15**，直接依赖版本固定在 `requirements.txt`。使用已安装的对应解释器创建新环境，例如：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

若系统没有 `py` 启动器，用已安装 Python 3.13.15 的绝对路径替代第一行中的 `py -3.13`。确认实际输出版本；不复制旧 `.venv`。各 run 的 `manifest.json` 记录实际 Python、平台及完整已安装分发版本。`requirements.txt` 固定直接依赖，`requirements.lock.txt` 保存本轮全部已安装分发版本；需要相同版本时使用后者安装并与运行清单逐项比较。不同系统或数学库可能存在小量浮点差异，不能承诺跨平台逐字节相同的模型文件。

## 3. Git clone 包含什么

当前 `.gitignore` 排除：

| 路径 | 含义 | 完整本地审计的要求 |
|---|---|---|
| `.venv/` | 本机 Python 环境 | 根据要求新建，比较版本 |
| `processed/*`，保留 README | 清洗航班、衔接、天气缓存和派生清单 | 从原电脑另行保存并核对，或在新副本重建 |
| `experiments/runs/*/data/` | 开发特征 pickle | 原 run 收据列出的文件必须实际存在 |
| `experiments/runs/*/predictions/` | 完整逐行预测 | 指标复核与模型比较需要 |
| `experiments/runs/*/models/` | 已拟合模型 | 解释与完整归档核验需要 |
| 根 `models/` | 模型目录 | 若有使用，另行保存 |

配置、清单、指标、图、日志和已执行 Notebook 可在 Git 中；文件是否实际跟踪以 `git ls-files` 为准。**Git clone 完整并不等于运行归档完整**。审计工具不会因某文件被忽略而跳过其 SHA：缺少模型、特征或预测会使该运行的完整收据核验失败。

从原电脑复制受信任的这些大文件时保留相对位置，以原 `manifest.json` 的字节数和 SHA-256 为准。pickle/joblib 是受信任本地产物；本审计仅逐块哈希，不反序列化。不要把从其他来源获得的 pickle 当作安全的通用数据交换格式。

## 4. 只读核验命令

在项目根目录使用环境内解释器：

```powershell
# 原交付清单检查；不训练，不联网，不改写文件。
.\.venv\Scripts\python.exe scripts/verify_downloads.py

# 单个运行；只向标准输出给出 JSON。
.\.venv\Scripts\python.exe scripts/verify_research_archive.py --run-id R0006

# 索引与实际 run 目录一起检查；正在运行的档案列为尚未封存。
.\.venv\Scripts\python.exe scripts/verify_research_archive.py --all

# 若最终账本存在，复核它指向的保存预测；不会再次 fit。
.\.venv\Scripts\python.exe scripts/verify_research_archive.py --final

# 输出必须使用尚不存在、位于运行档案之外的新 JSON 路径。
.\.venv\Scripts\python.exe scripts/verify_research_archive.py --all --output audit_reports/archive_check_001.json
```

`verify_downloads.py` 按 `tables/file_manifest.json` 核对原交付快照，包括其中列出的数据、部分脚本/说明文件，并验证 ZIP/GZIP 可读性。代码演进后旧快照中的脚本可能不同；按失败的具体路径区分源码演进与原始数据损坏，不把整个旧清单“全绿”当作当前计算代码的证明。当前计算源码使用各 run 的 Git 字节收据检查。

`verify_research_archive.py` 检查：

1. 索引 run_id 唯一性、档案位置、索引与 manifest 状态；失败、失效记录始终保留。
2. 每条 `outputs` 收据的实际本地字节数及 SHA-256，包括被忽略的预测、模型和 pickle；源文件收据核对记录的 `git_commit` 对应 blob。
3. 记录的输入清单自身的 SHA；它不自动解码原始航班/天气文件。原始下载内容由上面的独立下载核验入口检查。
4. 当前环境与当前直接依赖要求；每轮记录环境与当时提交的 `requirements.txt` 逐包比较。历史环境差异明确列出，不重写历史。
5. 完成的最终预测运行若存在，调用 `final_evaluation.verify_saved` 校验保存产物、目标/ID、最终指标及可用的单次访问账本。

`integrity_passed` 表示收据核验结果；`eligible_completed` 同时要求研究状态是 completed 且收据通过。索引将旧 completed 运行标为 invalidated 时，仍保留原执行状态，研究资格为 false。failed 即使收据完整，也绝不成为 completed。当前 running 运行明确列为 `unsealed_runs_skipped`，不宣称它已通过封存核验。

历史源码与今天的工作文件不同可以是正常演进；工具记录当前文件是否相同，判断历史来源时使用当时 Git blob。缺少该提交历史会报错；可从原仓库获取完整历史。R0001 预检是旧收据格式，只有单一源码哈希，审计会说明其缺项。

审计退出码非零表示完整性失败或当前要求环境不匹配。没有最终账本时，`--final` 明确报告尚无最终结果，不能将此解释为最终评估通过。默认 JSON 输出不修改任何归档，`--output` 拒绝覆盖既有文件及向运行目录写入。

## 5. P0→P4 重建顺序

下列命令展示实际入口。**仅在独立工作副本执行重算**；先为新研究链复制并调整 JSON，核对 `parent_run_id`、派生路径、`data_id` 和所有来源 run。这里使用未占用的 R900x 作为示例，执行前仍须核对索引与目录没有同名。

`run_pipeline.py` 要求执行源码和配置已提交且工作字节与该提交相同；调整后的新配置必须先在复现副本提交。清洗会写 `processed/`、部分 `tables/` 和展示 Notebook，因此不应在原运行目录下尝试重算。

| 阶段 | 已有配置/模块 | 示例入口 |
|---|---|---|
| P0 原始准备 | `configs/prepare.json` | `python scripts/run_pipeline.py --config configs/prepare.json --run-id R9001` |
| P0 事后 QA 审计 | `configs/audit_preparation.json` | 同入口，换配置及新 ID |
| P0 QA 修正历史 | `configs/rebuild_cohorts.json` → `configs/correct_boundary_quality.json` | 分别新 ID；最终主线使用 D0003 |
| P0 基线与 G0 | `configs/p0.json` | 同入口，新 ID；先确认 D0003 已存在 |
| P1 航班链 G1 | `configs/p1.json` | 同入口，新 ID |
| P2 机型准备 | `configs/prepare_aircraft.json` | 同入口，新 ID |
| P2 family 主线/variant 分支 | `configs/p2_family.json` / `configs/p2_variant.json` | 两个独立 ID |
| P3 机场运行 | `configs/p3.json` | 同入口，新 ID |
| P4 天气准备 | `configs/prepare_weather.json` | 同入口，新 ID；输出独立 W 数据集 |
| P4 实况→TAF | `configs/p4a.json` → `configs/p4b.json` | 两个独立 ID |
| P4 NOAA 补缺 | `configs/p4_noaa.json` | 单独分支，不参与主线特征选择 |

表中 `python` 统一指 `.\.venv\Scripts\python.exe`。现有示例配置保留原研究父关系，不能直接把它们当作已经重写好父关系的复现配置。修正准备脚本的旧失败记录仍保留；不要求重演已知失败才能运行修正版本。

开发执行共享 `build_features.py`、`train_models.py`、`evaluate_models.py`；固定三个 UTC 前向验证折、成熟标签和非负预测截断。`feature_cache.py` 支持通过显式 `feature_archive_path`、`feature_source_run_id` 复用验证过的开发特征；缺文件或收据不符会拒绝，不自动回退到其他数据。`fold_workers` 支持 1/3，`threads` 是每折资源配置，需考虑并行总内存。

## 6. P5 选择、完整分析与解释

主线六个完成运行齐全后，调用现有函数选择特征，例如在根目录启动环境内 Python，使用显式运行目录：

```python
from scripts.select_models import select_features, select_model

# 用复现链中实际完成的 G0/G1/G2 family/G3/G4A/G4B 替换。
feature_choice = select_features(mainline_run_dirs, output_dir="research/reproduction/feature_choice")
```

这两个变量由调用者提供，不存在自动寻找“最新运行”的默认规则。输出包括候选/逐月指标、排除分支、协议和收据。`select_features` 不训练模型。

固定选定特征后，用新 JSON 和新 run_id 完成：线性参照；决策树深度 8/16 × 最小叶 50/200 共四组；随机森林 200 棵、深度 16、`max_features=0.5`、最小叶 50/200 共两组，seed=42。使用同一个开发特征归档；只更改算法或一项参数。`model_type` 为 `decision_tree` / `random_forest`，参数放 `model_params`，其余实际特征、数据与预处理设置保持一致。配置通过同一 `run_pipeline.py --config ... --run-id ...` 执行；当前未提供一条自动生成并执行全部候选的命令。

```python
model_choice = select_model(feature_choice["selected_run_dir"], algorithm_runs,
                            output_dir="research/reproduction/model_choice")
```

完整 DT/RF 网格缺一不可。选择按已提交的 `configs/model_selection_protocol.json`，输出实际晋级或拒绝理由，随后与 mean/median/carry 基线比较；主模型允许为基线。不得用 RMSE 覆盖主 MAE 决定，也不得根据区间显著性追加调参。

RQ1 完整分析使用 `complete_rq1.run(config, run_dir)`，规则来自 `configs/rq1_protocol.json`。共享的 `rq1_standardization.py` 冻结开发参考，输出共同支持、标准化、区间、阈值与网络表。完整单航段 EDA 使用 `analyze_single_flights.run`。`configs/p5_analysis.json` 已由 `run_pipeline` 的 `analysis_only=true` 模式实际执行；复制到新研究链时应调整来源运行编号并先提交。`select_features` 与 `select_model` 模式分别保存主线特征选择、有限算法选择及开发解释，后者在新运行中刷新06展示，不修改已完成RQ1归档。

单独解释已训练模型也可运行：

```powershell
.\.venv\Scripts\python.exe scripts/explain_models.py --source-run experiments/runs/R9006 --output-dir research/reproduction/explanations_R9006
```

该入口仅读取开发特征和已拟合模型，不重新 fit。置换、PDP、系数与网络均为描述性结果，不是因果效应。

## 7. P6 冻结与最终复核

**以下冻结调用是研究决策步骤，不能作为日常审计命令自动执行。** 在全部开发候选、方法审查和科学配置确定后，显式调用：

```python
from scripts.select_models import create_freeze
receipt = create_freeze("research/reproduction/model_choice/model_selection_decision.json",
                        "research/reproduction/frozen_selection.json")
```

它验证选择来源已完成、证据未变、执行源码已提交，生成与 `final_evaluation` 一致的配置/协议/数据/源码 pins、payload SHA 和文件字节 SHA；不打开最终目标，不创建访问账本。冻结 JSON、最终配置及 RQ1 冻结参考应在正式访问前留档并提交。

最终 JSON 至少含 `mode="final"`、已冻结文件路径和 `freeze_manifest_sha256`，以及统一入口所需的 `stage`、`change`、`parent_run_id`；科学设置由冻结文件决定，不再调参。使用新 run_id 通过同一 `run_pipeline.py` 执行。训练只使用 4–7 月预测窗且 `label_time < 2026-08-01 UTC` 的成熟标签；只评估冻结模型与三个基线。访问账本以独占创建方式产生，即使运行失败也保留记录，不能自动绕过或删除。

完成后直接复核已保存预测：

```powershell
.\.venv\Scripts\python.exe scripts/final_evaluation.py --verify-run experiments/runs/R9XXX
```

`R9XXX` 是说明占位符，替换为真实最终预测运行 ID。该入口不重训，不读取 raw/特征，也不创建新账本；若预测或指标缺失，不能只凭图表宣称复核通过。

最终 RQ1 是独立 `mode="rq1_final"` 运行，配置包含 `prediction_final_run_id` 及开发期 `rq1_frozen_reference_path`，另用新 ID。它会读取 4–8 月描述性资料，必须在正式最终预测评估完成后执行；不能把最终描述结果用于修改已冻结预测模型。07 Notebook 可读取 completed 预测源，将综合展示写入新的 RQ1 运行目录。

完整复现使用 `mode="reproduce_final"`，保留原正式ledger、原completed归档及大文件。配置至少包含该mode、stage/change/parent_run_id及**原**freeze_manifest_path/SHA；统一入口分配新run_id。实现会验证唯一账本已完成、原结果与冻结身份相同、全部源码和输入pins相同，随后按共享逻辑重建和重拟合，逐行核对原始及截断预测，固定绝对容差1e-10、相对容差0。原账本前后字节哈希必须一致，不提供删除账本或另造正式测试声明的捷径。

复现收据为新run中的 `reproduction_verification.json`、`reproduction_prediction_differences.csv`、`final_feature_fingerprints.json` 与独立07 Notebook。`--verify-run` 仍专用于原正式run；不能把它用于复现run而期望生成新的正式账本证明。特征或预测不一致会保留失败档案，不能事后放宽容差假称成功。

## 8. P7 报告与交付核对

报告中的模型、机场、天气、阈值和解释结论应链接到相应运行的表/图及收据，并区分开发选择、最终预测、最终 RQ1 和补充敏感性。中文 Notebook 读取共享脚本或归档；英文课程报告和中文解读通过 `scripts/build_report.py --config <报告配置>` 使用已完成归档生成，PDF使用 `scripts/render_report_pdf.py`。演示文稿与视频入口见 `reports/presentation/BUILD.md`。这些构建器拒绝覆盖既有成品；实际交付仍需逐页目视检查，不把构建成功等同于完整研究完成。

交付时同时保存：Git 提交与分支、完整实验索引、失败/失效记录、冻结协议与选择理由、最终账本、已执行 Notebook/HTML、模型与逐行预测/特征的大文件，以及新路径中的审计 JSON。只复制 Git 仓库而不携带忽略产物，应明确标为“源码与摘要可用，完整归档尚待恢复”。
