## 下载、恢复和核验

使用完整 Git 历史并选择研究分支。此次不更改 `main` 或仓库默认分支。

```powershell
git clone --branch codex/apr-aug-research https://github.com/GeoRus63/Airline-delay.git airline_delay
cd airline_delay

# 此恢复脚本只用 Python 标准库（Python 3.11+），不加载模型、不训练。
python scripts/restore_research_artifacts.py
```

脚本会把 ZIP 缓存在 `tmp/research-artifacts-downloads/`，先校验整包及每个成员，再恢复到原 `experiments/runs/<run_id>/models/` 和 `predictions/`。已存在且相同的文件跳过；遇到不同内容会停止，拒绝覆盖。若仅需最终结果：

```powershell
python scripts/restore_research_artifacts.py --runs R0028 R0030

# 本地只读核验，无网络访问。
python scripts/restore_research_artifacts.py --verify-only

# 可恢复到一个独立的空目录，避免触及现有工作副本。
python scripts/restore_research_artifacts.py --runs R0028 --root D:/Airline-delay-restore
```

仅恢复部分 run 时，核验也传入相同的 `--runs`。手动下载可按清单选择 ZIP，解压到项目根目录，然后使用 `--verify-only`。不要把 ZIP 解压成重复的嵌套项目目录。

## 恢复边界

- GitHub 页面中的“Source code”下载只含 Git 跟踪文件；模型与完整预测需另下载上述附件。
- `processed/`、各 run 的 `data/` 和其他本地生成中间表不在本次模型预测包内。它们仍需另行同步或在独立副本重建，不能把此 Release 称为完整计算备份。
- 加载模型请使用[锁定环境](../requirements.lock.txt)及原 Python 3.13.15，具体见[迁移与运行](迁移与运行.md)。恢复脚本只做字节校验，不反序列化 joblib。
- 所有归档保留原 2024 机型参考结果。后续新版用新 run_id、配置和归档版本；不覆盖本次 Release、F0001、原正式账本或历史报告。

仓库保留忽略 `models/`、`predictions/` 的规则，避免把大文件重复写入 Git 历史；版本关联、清单、校验收据和恢复代码由 Git 管理，实际文件由 Release 提供。
