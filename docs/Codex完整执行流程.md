# 新电脑 Codex 完整执行流程

## 目标与起点

接手后在这台新电脑完成整个 Airline Delay 项目：从仓库原始数据出发，实际跑出清洗数据、特征、EDA、两项研究结果、模型比较、图表和报告，并提供可重复执行的入口。

现有数据范围为 2026 年 4–8 月、3,057,590 条 BTS 航班、355 个 AirportID。研究设计以 [完整项目计划](完整项目计划.md) 为准；环境步骤见 [迁移与运行](迁移与运行.md)。当前仓库完成的是原始下载与完整性核对，已有准备脚本，尚未执行五个月全量处理。

## 接手后的阅读与运行入口

先读根目录 `README.md`、`下载完成说明.md`、本文件、`完整项目计划.md`、`数据与字段说明.md` 和 `机型说明.md`，再查看现有脚本。任务书和两篇论文在 `references/` 中；报告的文献讨论要基于原文。

在新电脑安装 Python 3.12，按 `requirements.txt` 创建 `.venv`。下面命令的 `python` 均指该虚拟环境解释器。先核对原始文件，再修改准备代码；下载源文件保持原样，派生结果写入 `processed/`。

```bash
python scripts/verify_downloads.py
python scripts/prepare_flights.py --check
```

`verify_downloads.py` 对应当前交付快照，之后正常编辑代码会改变其代码/文档哈希；原始数据哈希继续作为输入版本依据，完成项目时另存新的运行清单。

## 1. 全量航班与同机衔接

现有入口：

```bash
python scripts/prepare_aircraft.py
python scripts/prepare_flights.py
```

阅读并运行 `notebooks/01_航班清洗与衔接.ipynb` 所调用的同一代码路径，修复实际运行问题。核心步骤如下：

- 读取五个月航班，保留 `source_file`、`source_row`、`flight_id`，核对总行数 3,057,590。
- 用 AirportID 统一机场身份；按机场时区转换 UTC，处理 `2400`、跨日与夏令时；保留原始时间字段。
- 标记重复键、缺失尾号、取消、改道和异常时间。先建立尾号序列及中断关系，再筛选有效衔接。
- 按同机计划出发顺序找相邻航段，用实际时序、衔接机场和间隔核验，记录全部候选及排除原因。
- 保留原始正负延误与非负延误两种口径；RQ1 净变化用两端非负延误之差。
- 机型以 2024 参考表为主，2025 作覆盖对照；保留原始型号、family、variant 和未匹配状态。将机型实际连接至航班/衔接表；现有 `prepare_aircraft.py` 主要生成映射与覆盖表，这一步连接仍需实现。

应生成 `processed/flights_clean.csv.gz`、`connection_candidates.csv.gz`、`flight_connections.csv.gz`、`tables/cleaning_summary.json` 与 `connection_exclusions.csv`。更新字段字典；抽取跨日、取消中断、机场代码变化和重复键等实例，确认结果能追溯到原始行。

## 2. 天气标准化与逐航班特征

先运行现有天气准备入口：

```bash
python scripts/download_taf_text.py --prepare-validity
python scripts/prepare_weather.py
```

完整 TAF 原文已在本地；当前缓存下 `--prepare-validity` 可复用已下载批次。生成 `references/taf_validity.csv` 和 `processed/metar_observations.csv.gz`、`taf_segments.csv.gz`、`taf_bulletins.csv.gz`。

随后实现 `scripts/build_features.py` 和 `notebooks/02_天气与特征.ipynb`。本阶段尚未编写完成的工作包括 NOAA 质量筛选/融合、天气 as-of 连接、历史滚动统计和建模总表。

1. 读取 NOAA 原始 PSV 及官方字段说明，按质量码处理记录，统一风速、能见度、云底、温度和降水单位。IEM 为主源，NOAA 用于补充合格的缺失观测/字段；为每个补充值记录来源。先比较重叠观测，再合并。
2. 设 `prediction_time` 为上游实际到达 UTC，`label_time` 为下游实际出发 UTC，`target` 为下游非负出发延误。RQ2 使用有效衔接中 `prediction_time < label_time` 且标签可用的记录，包含上游准点记录；不套用 RQ1 的上游至少 15 分钟筛选。隔夜衔接单列误差和样本数。
3. 实况以观测后 5 分钟可用为假设，取预测时点之前最近可用记录，观测年龄不超过 120 分钟。记录观测时间、可用时间、年龄及来源。
4. TAF 先按预测时点挑选最新可用公告版本，再在该公告内找覆盖下游计划出发时刻的分段。处理修订、取消、NIL、FM、TEMPO 和概率段；主预报和临时/概率风险分别保留。若下游计划出发时刻已早于预测时点，查询时刻用两者较晚者，并记录该规则。取消版本不回退成仍然有效的旧预报。
5. 12 个机场无 TAF、3 条原文缺失、各源缺测日均保留明确状态。预报缺失不删除整条航班，也不解释为晴天。若该最新公告无法确认有效窗，则相应 TAF 特征记缺失。
6. 动态特征只使用预测前已完成事件：同机过去 24 小时航段数及延误、机场过去 60 分钟已出发数量及平均延误。计划未来 60 分钟进出港负荷使用计划时刻，记录其静态计划假设。窗口起始历史不足时保留覆盖标记。
7. 按研究计划的 G0、G1、G2、G3、G4a、G4b 分组保存变量，保留天气缺失标记。数据填补、类别编码和缩放进入模型训练流水线，不在全数据上拟合。

生成 `processed/model_features.csv.gz`、`tables/feature_dictionary.csv`、`feature_availability_checks.csv` 和 `weather_join_coverage.csv`。每行使用唯一 `connection_id`，列出每个变量的含义、单位、来源、生成规则、可用时间和所属特征组。

检查连接前后行数、键唯一性、天气时差、预报版本/有效窗、历史特征截止时间，并用原始样例验证。观察到的未来数据不得回流成事前特征。

## 3. 开发期 EDA

实现并执行 `notebooks/03_EDA.ipynb`。开发分析使用 4–7 月；8 月提前仅检查数据文件、字段和覆盖。

按计划产出延误分布/右尾、日期与计划小时变化、机场/航司/航线支持、机型覆盖、天气缺失图、有效衔接样本流，以及上游延误 × 计划周转热力图。每图写清样本范围、坐标/颜色单位、实际发现和它对后续模型的影响。重要分组同时显示样本数；大样本图使用聚合或透明度控制。

图表保存到 `figures/eda/`，可复核的汇总表保存到 `tables/eda/`。Notebook 的解释根据实际输出填写。

## 4. RQ1 机场分析

实现 `scripts/analyze_rq1.py` 和 `notebooks/04_RQ1机场分析.ipynb`。先在 4–7 月确定分析规则；模型方案冻结后再扩展到 4–8 月最终描述。

- 主样本：有效同机衔接、计划非隔夜、上游非负到达延误至少 15 分钟。
- 输出机场样本量、均值/中位数净变化、吸收/放大/不变比例、累计增加、累计减少和累计净变化。减少延误不等于下游准点。
- 主比较对象为机场；仅用上游延误与计划周转做共同支持标准化。机场使用同一分层集合和参考权重，保存保留样本比例。支持不足的机场列描述性结果；若共享支持过窄，缩小比较集合并说明覆盖范围。
- 用共同日期块重抽样估计区间，保留同日共同冲击。阈值敏感性比较 >0、≥5、≥15 分钟，在共同机场上比较方向与排名稳定性。
- 绘制机场网络：节点大小为有效衔接数、颜色为标准化平均净变化、有向边宽为航线航班数；累计分钟单独展示。提供机场排名/区间图、周转热力图、敏感性图和必要的辅助分层。

保存 `tables/rq1/`、`figures/rq1/`，明确回答哪些机场表现出吸收/放大、差异有多大、是否在阈值/月份之间稳定。机场汇总解释为样本中的关联表现。

## 5. RQ2 前向验证、模型比较和因素分析

实现 `scripts/train_models.py`、`scripts/evaluate_models.py` 和 `notebooks/05_RQ2预测与解释.ipynb`。准备同一批连接 ID 的时间切分清单：

| 开发折 | 训练预测时点 | 验证预测时点 |
|---|---|---|
| 1 | 4 月 | 5 月 |
| 2 | 4–5 月 | 6 月 |
| 3 | 4–6 月 | 7 月 |

全部以 UTC 月初半开区间划分；每折训练标签必须早于该折训练截止点。飞机序列可跨月延续，历史特征按每条预测时点截止。记录每折样本数、日期范围和严重延误比例。

先完成训练均值、训练中位数、上游延误原样传递三个基线；再按研究计划比较线性回归、决策树和随机森林。固定模型逐组加入 G0–G4b，固定特征比较算法。插补、编码、缩放仅在该折训练数据拟合；统一将预测截断为非负。

保存每折预测明细和指标，比较加权 MAE、RMSE、跨月稳定性及分组误差；天气增量在同一批样本上比较，同时另报有天气覆盖子集。图表包括特征组 MAE 改善、算法对比、普通/严重延误误差、主要机场/航司/机型误差和残差分布。解释使用验证期分组 permutation importance、线性系数、少数关键变量的 PDP；相关变量按组解释。XGBoost/ALE/网络中心性不作为完成核心项目的条件。

开发完成后保存 `tables/model_selection.json`：特征组、超参数、种子、预处理、阈值、选型依据与冻结时间。然后用合格的 4–7 月成熟标签重拟合冻结候选，在 8 月 UTC 窗评估一次。所有冻结候选都可在同一 8 月样本上报告结果，但不再据此调参或重新选特征。当地 8 月但跨出 UTC 主窗口的记录单列。

保存 `tables/rq2/`、`figures/rq2/`、`processed/predictions/` 和 `models/`。回答：哪些变量有稳定增益、复杂模型是否值得、在哪些情况误差最大，以及最终测试上的表现。
