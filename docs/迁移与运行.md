# 搬迁到另一台电脑 / Move to another computer

## 从 GitHub 获取项目

```bash
git clone --depth 1 https://github.com/GeoRus63/Airline-delay.git airline_delay
cd airline_delay
```

仓库包含原始数据、参考表、脚本、Notebook 和说明文档。保留克隆后的相对目录结构；脚本根据自身位置找项目根目录。虚拟环境和大体积中间数据在新电脑创建；研究日志、每轮配置、指标、图表和已执行 Notebook 提交到 Git。预测明细与模型另行保留，位置及哈希记入运行清单。`.gitattributes` 禁用自动换行转换，让跨系统克隆后的文件与下载校验值一致。

原始航班、气象档案和飞机资料已经存入仓库。来源和哈希见 `sources.json` 与 `tables/file_manifest.json`；覆盖见 `下载完成说明.md`。数据下载完成与数据处理完成是两个阶段：本次进行前者，清洗、天气匹配、EDA 与模型在目标电脑运行。

## 先核对搬迁文件

在项目根目录打开终端：

```bash
python scripts/verify_downloads.py
```

该脚本只用 Python 标准库，检查清单内数据、参考表、脚本与文档的文件大小和 SHA-256，并检查 ZIP/GZIP 是否可读。不会联网、改写数据、训练模型。若 Windows 中 `python` 尚未配置，可用 `py -3.12` 替换。

## 安装环境

建议使用 Python 3.12。Windows PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m jupyter lab
```

macOS / Linux：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m jupyter lab
```

启动后先打开 `notebooks/00_数据清单.ipynb`。Notebook 使用普通 `Python 3` 内核；从该虚拟环境启动 Jupyter 即可。下面的 `python` 均指这个新环境里的解释器。模型不需要 GPU。

## 让 Codex 完成整个项目

环境就绪后，在 Codex 打开项目目录，按 [Codex 完整执行流程](Codex完整执行流程.md) 开工。该文件按渐进顺序列出现有命令、待实现代码、实验留档要求和最终成品；先运行基础分析，再逐组增加变量和比较模型。

当前已经提供的准备代码包括 `prepare_aircraft.py`、`prepare_flights.py`、`download_taf_text.py --prepare-validity` 和 `prepare_weather.py`。它们需要在新电脑运行并修复实际问题；后续天气融合、特征连接和分析由同一个 Codex 接续实现。

## 重新下载入口

正常迁移不需要重新下载。若确实缺文件：

- `scripts/download_data.py`：重取缺少的 METAR 和 TAF 分段文件，已有文件复用。
- `scripts/download_taf_text.py`：重取缺少的完整 TAF 报文批次，已有批次复用。
- `scripts/download_noaa_supplement.py`：重取缺少的 NOAA 备用原始档案。
- BTS 月度 ZIP 的官方地址和飞机 B-43 来源见 `sources.json`。B-43 使用网站表单导出，仓库内已保存原始导出 ZIP 和两份年度参考表。

下载脚本使用系统 `curl`。Windows 10/11 通常已提供；首次下载时可在终端运行 `curl --version` 确认。离线使用仓库内数据不需要 curl。
